A command `gaia` (on PATH) talks to a live Gaia editor (Nu's game editor) running this project. Usage:
gaia: talk to Gaia's agent bridge from a terminal. No Python needed: bash, netcat (OpenBSD `nc`, with -U and -N)
and coreutils (base64, stat, grep) only.

The bridge is a Unix socket ($NU_GAIA_AGENT_SOCKET, default $XDG_RUNTIME_DIR/nu-gaia-agent.sock). Each request is
one JSON line {"id","op","args"[, "timeout_s"]}; each reply is one JSON line, printed as is.

Usage:
  gaia ping | status | hierarchy | undo | redo | reload_code      one request, print the JSON reply
  gaia eval 'F# CODE' [TIMEOUT_S]       run F# in the live editor; "-" reads the code from stdin
  gaia advance FRAMES                   step the game FRAMES frames (at most 600)
  gaia inspect [ENTITY_PATH]            properties of an entity (no path: the selected screen)
  gaia log [SINCE]                      editor log
  gaia symbol NAME                      F# declaration of a Nu symbol
  gaia docs WORD...                     search Nu's XML docs (Nu.xml; set NU_XML_DOC) for members matching all words
  gaia checkpoint NAME [restore|delete] save / restore / delete a named world checkpoint
  gaia diff FROM [LIMIT]                what changed since checkpoint FROM
  gaia assert 'PREDICATE' [FRAMES] [PROBE] [noadvance]   run the game FRAMES frames; check an F# bool each frame
  gaia resolve_exception CHOICE         answer a pending editor exception (as gaia_resolve_exception)
  gaia capture [OUT.png] [game]         read the next frame back from the renderer into a PNG; prints the path.
                                        "game" captures the game view without editor panels.
  gaia frames COUNT EVERY [OUTDIR] [editor]   COUNT captures, advancing EVERY frames between them; prints paths
  gaia restart                          stop the Gaia that run_gaia_headless.sh started and launch it again
  gaia raw OP ['{"json":"args"}']       any other bridge op with raw JSON args
Exit status: 0 when the reply has "ok":true (and, for eval/assert, the code compiled and ran/passed), else 1.

A live Gaia editor is running the project. Compiling is not checking: after changing the game, reload the code (gaia reload_code), then check in the running game that the change does what was asked, with a test that can fail, such as gaia assert over enough frames to see the behaviour. If the check fails, your idea of the cause may be wrong; look again before changing more code.
