## What the paper is
A debugging tool interface for LLM agents on SWE-bench-style program repair (Python). Instead of GDB/PDB-style statement stepping, ADI exposes a function-level view. The unit is a Frame Lifetime Trace (FLT) = (fid, fid_caller, args, ret, trace), where trace is the ordered statements executed in one function invocation with per-statement state diffs (variable, old, new) and callee frame ids (Sec. 4.1, p. 8). Eight commands (Sec. 4.2, pp. 9-10): `break`/`clear` (function-level conditional breakpoints), `continue`/`prev` (move along the execution timeline between breakpoint hits), `step-into(fid)`/`step-out` (move to a callee/caller frame), `call-tree` (read-only 3-level downstream call hierarchy), `execute(fid, stmt, lineno, k)` ("what-if": re-execute the program to the k-th visit of a line in a frame and inject a statement, without changing source or the canonical trace). Implementation (Sec. 5.3.1, p. 13): Python `sys.settrace` applied only to the currently inspected frame; only a lightweight function-level frame sequence is recorded globally; loops are summarised (first and last iteration, middle shown as a "skipped" block); `execute` uses `exec` plus `PyFrame_LocalsToFast`. The agent that uses it, FramePilot, is a ReAct agent with a 4-stage workflow (code orientation, issue reproduction, root-cause analysis, patch implementation) (Sec. 5.3.2).

## Key results (with locators)
1. **Motivating example (Sec. 2, Figs 1-3, pp. 3-5).** astropy-12907 (a silent logic bug, no failure signal). A post-mortem agent loops on "re-run the test, output unchanged". A PDB agent spends "29 PDB interactions, without clear progress". With ADI the agent needs three ADI calls (Fig. 3): `call-tree` shows `_cstack` returning a wrong matrix, a conditional `break` on `_cstack`, then a targeted `execute` print. Illustrative, one task.
2. **Main result (RQ1, Table 1, p. 15).** SWE-bench Verified (500 tasks): FramePilot + Claude-Sonnet-3.7 resolves 319 (63.8%) at average cost $1.28; Claude-Tools (the Claude Code foundation agent, numbers taken from published results, cost "calculated from trajectories") 316 (63.2%) at $3.95; SWE-agent 291 (58.2%); mini-SWE-agent 264 (52.8%) at $1.43. SWE-bench Lite (300): FramePilot 152 (50.7%). Other models with FramePilot on Verified: Sonnet-3.5 256 (51.2%, $0.58), GPT-4o 181 (36.2%, $0.93), Qwen3-32B 157 (31.4%). The margin over Claude-Tools is 3 tasks. FramePilot "uniquely solves two tasks on the entire SWE-bench leaderboard which none of the rest baselines could" (p. 15).
3. **Ablation: same agent, three tool settings (RQ1, Table 2, pp. 15-16).** BaseAgent (file edit + bash, post-mortem only), BaseAgent_pdb (naive PDB session), FramePilot (ADI). Sonnet-3.7, Verified: 275 (55.0%, $1.02) / 279 (55.8%, $1.62) / 319 (63.8%, $1.28). Lite: 130 / 133 / 152. FramePilot over BaseAgent: +7.5% to +16.0% resolved tasks across four LLMs, over BaseAgent_pdb +10.6% to +16.0% (all relative, from task counts). Correct-location rate also rises (Sonnet-3.7 line-level 47.0 -> 51.2%). **Giving the agent plain PDB bought +4 tasks (+0.8 pp) for +$0.60 per task; function-level ADI bought +44 tasks (+8.8 pp) for +$0.26.**
4. **Why PDB loses (p. 16).** With Sonnet-3.7, BaseAgent_pdb invokes `next` 10.1 times on average in the 191 tasks where it tries debugging; a manual analysis of all 191 attempts finds that the agent abandons the attempt in 53% of them.
5. **Plug-in generality (RQ2, Table 3, p. 16).** Verified: mini-SWE-agent+ADI 264 -> 292 (+10.6% relative, $1.43 -> $1.57, Sonnet-3.7); GPT-4o 108 -> 128 (+18.5%, $0.98 -> $1.16); AutoCodeRover+ADI 231 -> 248 (+7.3%, Sonnet-3.5, $0.74 -> $0.86); 192 -> 204 (+6.2%, GPT-4o). In absolute percentage points of the 500 tasks: +5.6, +4.0, +3.4, +2.4. ADI is added by prompt instructions and an optional dynamic-analysis stage (Sec. 5.3.3).
6. **Usage characteristics (RQ3, Fig. 8, pp. 16-17).** ADI is invoked in 73% (Lite) / 71% (Verified) of tasks with Sonnet-3.7, 63%/58% Sonnet-3.5 (as read from the figure labels, approximate pairing), and 31%/28% with Qwen3: stronger models use it more (Finding 3). `break` is the most used command (mean 2.5 per task) then `continue` (2.4). For the 62 tasks solved by FramePilot but not by BaseAgent (Sonnet-3.7, Verified), ADI is called 6.39 times per task on average. With Sonnet-3.7, `execute` is used in 44 tasks (3.1 calls each), `call-tree` in 16 tasks (1.0 each).
7. **FLT component ablation (Table 4, p. 17; Lite, Sonnet-3.7).** Basic 130 resolved ($0.90); +statement trace 142 ($1.14); +args 145 ($1.23); +return value (FramePilot) 152 ($1.26). The statement-level trace contributes most (+12 of +22). (Table 4 costs differ from Tables 1-2 ($1.26 vs $1.28; $0.90 vs $1.02); the text does not say why, likely Lite-only versus overall.)
8. **Overhead (Sec. 5.3.1, Sec. 6, pp. 13, 18).** Tracing the buggy frames raises average test execution time from 0.68 s to 0.87 s. ADI re-executes the program 5.19 times per task on average, about 4 s of total execution per task. No non-determinism effects observed (the agent is told to write minimal reproduction scripts; external libraries are not traced).
9. **Scope limits stated (Sec. 6, pp. 18-19).** Python only; best for bugs whose diagnosis depends on function-level data flow, control flow and state mutation; concurrency, memory leaks and interactions "spanning many shallow calls" may be poorly supported; gains depend on how well the host agent invokes the tool; temperature 0, $4 per-task budget (following SWE-agent), official SWE-bench Docker environment; the failing developer tests are held out and the agent writes its own reproduction script (Sec. 5.3.1).

## Verbatim quotes
1. (p. 2, Sec. 1) "each atomic command provides only a sliver of state information but incurs the substantial cost of a complete LLM inference cycle."
2. (p. 2, Sec. 1) "When attempting to operate fully autonomously, agents easily exhaust their computational budget or halt in unproductive debugging loops"
3. (p. 7, Sec. 4) "ADI does not pre-compute a complete statement-level trace for an entire execution. Instead, it first records a lightweight function-level frame sequence and constructs a detailed Frame Lifetime Trace only for the frame currently selected by the inspection index."
4. (p. 16, Sec. 5.4.1) "Our manual analysis of all 191 of these attempts reveals that this inefficient process leads the agent to abandon its attempt in 53% of them."
5. (p. 17, Sec. 5.4.3) "stronger LLMs are more adept at leveraging ADI, allowing them to amplify their inherent analytical capabilities"
6. (p. 19, Sec. 6) "bugs involving concurrency effects, memory leaks, or interactions spanning many shallow calls may be less well supported by the current FLT abstraction"

## Corrections to the current literature-review.md entry (C12)
Entry: "**C12. Agent-centric Debugging Interface (ADI).** Xiang ... *FSE 2026* (per arXiv). arXiv:2604.24212 ... Finding: a function-level debugging interface with a Frame Lifetime Trace replaces line-by-line debugger stepping, which is too costly for agents. 63.8% on SWE-bench Verified at about USD 1.28 per task, and +6.2% to +18.5% when added to existing agents."
- **Title/venue:** the paper's title is "Empowering Autonomous Debugging Agents with Efficient Dynamic Analysis"; "Agent-centric Debugging Interface (ADI)" is the system name. Venue is now confirmed from the paper itself (Proc. ACM Softw. Eng. 3(FSE), FSE031, doi 10.1145/3797126, July 2026), not only "per arXiv". Citation should use the real title and the ACM DOI.
- **"+6.2% to +18.5%" is a relative gain in the number of resolved tasks** (Table 3), not percentage points. In absolute terms it is +2.4 to +5.6 pp on 500 tasks (e.g. 264 -> 292 is +10.6% relative, +5.6 pp). Also only two host agents x two LLMs each.
- **"63.8% ... at about USD 1.28":** correct, but the comparison to the "highly-optimized" Claude-Tools agent (63.2%) is a 3-task margin on one run at temperature 0, with the baseline's number taken from published results, so "slightly outperforming" is not a significant difference. The isolating evidence is the BaseAgent / BaseAgent_pdb / FramePilot ablation on the same ReAct scaffold (55.0 / 55.8 / 63.8%), which the entry omits; the full-system win alone would not isolate the interface.
- **Missing nuance on "line-by-line stepping is too costly":** supported by a measured comparison with a naive PDB interface (cost $1.62 vs $1.28 vs $1.02 for post-mortem only; PDB resolved only +0.8 pp more than post-mortem; 53% abandoned debugging attempts). The paper does not test intermediate granularities (e.g. line stepping with summarised output).
- **Missing:** ADI relies on re-executing a deterministic reproduction script under on-demand tracing (5.19 re-executions per task); it is not an interface to a long-lived mutable process. Python/SWE-bench only. Effect depends on model strength (invocation rate 71% for Sonnet-3.7 vs 28% for Qwen3).

## Design relevance
- **Granularity result transfers to eval steps.** One tool call should return a structured, summarised view of a bounded unit (here a function invocation with args, return value and a state-diff trace) instead of one fragment per call. For Gaia the analogue is a "world diff for this eval/tick window" (entities added/changed, property old -> new) rather than separate getters; the +12-task gain from the statement trace, and the PDB loss, argue for putting the diff in the tool result.
- **Conditional breakpoints on a function-level unit** map to "advance time until predicate P holds, then return the diff/frame" (the `break` + `continue` pair): one call replaces tens of single-step calls. Keep the output bounded (ADI bounds `call-tree` to 3 levels and collapses loops to first/last iteration).
- **`execute` = "inject a statement in a past context without changing source or canonical trace"** corresponds to evaluating a probe against a snapshot copy of the world; ADI does this by re-execution, which is cheap for a deterministic script but only works if the run is replayable. Gaia needs deterministic replay (seeded RNG, scripted inputs) or snapshot restore to support the same pattern.
- **Naive wrapping of a human debugger can be net-negative on cost** (PDB variant +$0.60 per task for +0.8 pp, 53% abandoned), so do not expose raw REPL/inspector stepping commands as the main inspection route.
- **The tool-definition format is public (Fig. 7, p. 14):** one `adi` function with an `action` field and a short per-action list. This is a data point for E3-style description decisions (one tool, enumerated actions, terse text), though the paper does not ablate it.

## Limits / credibility
- Peer-reviewed at FSE 2026 (published in PACMSE, CC BY). Credibility-gate label suggestion: `eligible_for_claim_subject_to_article_appraisal` for "function-level trace interface beats naive PDB on SWE-bench with the same agent"; it does not transfer to live editors, other languages or non-test-gated bugs.
- One run per cell, temperature 0, no confidence intervals; SWE-bench Lite/Verified are Python-only and public (contamination possible for all agents). Baseline numbers for other agents come from published results, not re-runs; cost for Claude-Tools / mini-SWE-agent is "calculated from trajectories", not reported by the sources.
